## 〇、决策记录

| # | 决策项 | 结论 | 决定方 |
| --- | --- | --- | --- |
| A | 命令名语言 | **中英对等**：`/work` ≡ `/作品`，两名完全等价，可混搭 | 用户 |
| B | 参数形式 | **严格全选项**：不接受位置参数，一律 `--long` / `-s` | 用户 |
| C | 命令结构 | **两级命令空间**：`/命名空间 子命令`，为未来功能扩展预留 | 用户授权代定 |
| D | `/安利` 参数 | **补齐全部字段**：author/type/summary/tags/link/source | 用户 |
| E | 旧命令过渡 | **不保留**：`COMMAND_START` 收紧后必然不兼容，一次切换 + 群公告 | 代定 |

### C 项的取舍理由（重点说明）

当前只有 7 个命令，扁平结构完全够用。但站点功能远不止作品库——README 的功能一览里还有**书评打分、话题论坛、同人创作、选章下载、管理员后台**，这些日后大概率都要有机器人命令。若采用扁平结构，命令数会膨胀到 20+，届时再改结构就是一次破坏性重构，且群友的使用习惯要重学一遍。

因此现在就把命名空间定下来：**日常高频命令给一级快捷别名（永久保留，非过渡兼容），结构上归属二级命名空间**。群友打 `/搜索 -k 诡秘` 和 `/作品 搜索 -k 诡秘` 都能用，`/帮助` 按命名空间分组展示，日后新增 `/论坛 发帖` 时有现成的位置可放。

代价：群友日常输入确实变长了（`/搜索 --keyword 诡秘` vs 原 `/搜索 诡秘`），这是 B 项「严格全选项」的必然结果，已用快捷别名和短选项 `-k` 缓解。

## 一、现状（改造前）

所有命令走 `on_command(...)` + `rule=to_me()`，参数用 `event.get_plaintext()` 手工切前缀，**零选项解析**。

配置（`qqbot/.env.prod`）：

```
COMMAND_START=["/", ""]   # 空前缀 → 裸「热门」也触发
COMMAND_SEP=["."]
```

| # | 插件 | 命令（含别名） | 参数现状 | 权限 |
| --- | --- | --- | --- | --- |
| 1 | `works.py` | `热门` / `hot` | 无（limit 硬编码 5） | 全员 |
| 2 | `works.py` | `搜索 <关键词>` / `search` | 位置参数，limit 硬编码 10 | 全员 |
| 3 | `works.py` | `安利 <作品名>` / `recommend` / `安利作品` | 位置参数，**只传 title** | 全员 |
| 4 | `auth_code.py` | `绑定 <验证码>` / `bind` / `验证注册` | 正则抽 4~8 位数字 | 全员 |
| 5 | `group_member_sync.py` | `sync_member [all\|群号,群号]` | 位置参数，逗号分隔 | SUPERUSER |
| 6 | `avatar_sync.py` | `sync_avatar` | 无（limit 硬编码 100） | SUPERUSER |
| 7 | — | *(缺失)* | 无 `/help`，命令发现全靠 README | — |

### 现状问题

1. **参数能力被浪费**：后端 `BotWorkSubmitIn` 已支持 `author` / `type` / `summary` / `tags` / `links` / `source_work_id`，插件只传了 `title`。群友想补作者/类型只能上站点手改。
2. **命名不统一**：4 个中文命令 + 2 个下划线英文命令（`sync_member`）。
3. **空前缀误触风险**：`COMMAND_START` 含 `""`，群友聊天里出现「热门」二字就可能触发机器人。
4. **无帮助系统**，无扩展结构。
5. **解析脆弱**：`_cmd_args` 只按固定字符串裁前缀，全角空格 / 全角横线 / 连续空格全部解析失败。

## 二、命名规范

### 2.1 命名空间（本次实现）

| 命名空间 | 中文对等名 | 权限 | 子命令 |
| --- | --- | --- | --- |
| `work` | `作品` | 全员 | `hot` `search` `add` |
| `auth` | `账号` | 全员 | `bind` |
| `sync` | `同步` | SUPERUSER | `member` `avatar` |
| `help` | `帮助` | 全员 | —（一级命令，无子命令） |

### 2.2 子命令中英对等表

| 英文 | 中文对等 | 归属 |
| --- | --- | --- |
| `hot` | `热门` | work |
| `search` | `搜索` | work |
| `add` | `安利` | work |
| `bind` | `绑定` | auth |
| `member` | `成员` | sync |
| `avatar` | `头像` | sync |

**中英可混搭**：`/work 搜索`、`/作品 search` 与 `/work search`、`/作品 搜索` 完全等价。实现上把 4 种组合同时注册为同一 handler 的别名。

### 2.3 一级快捷别名（永久保留）

高频命令额外提供一级形式，**是规范的正式组成部分，不是过渡兼容**：

| 快捷形式 | 等价于 |
| --- | --- |
| `/hot` `/热门` | `/work hot` |
| `/search` `/搜索` | `/work search` |
| `/recommend` `/安利` | `/work add` |
| `/bind` `/绑定` | `/auth bind` |

管理员命令（`/sync …`）**不提供快捷别名**：低频 + 误触代价高。

> 注：`/安利` 的英文快捷名沿用现有 `recommend`（群友已习惯），规范内主名是 `add`。

### 2.4 命名规则（约束未来新增命令）

1. 命名空间与子命令一律 **kebab-case 英文 + 对等中文别名**，禁止下划线、禁止驼峰。
2. 新增命名空间必须在本文件 §2.1 登记，避免命名冲突。
3. 每个命令必须提供 `-h/--help`，并在 §三 补全 usage 段落。
4. 短选项必须从 §3.1 全局分配表取，**禁止同一字母在不同命令里表示不同含义**。
5. 破坏性 / 不可逆操作的选项**不给短选项**，强制打全名。

### 2.5 未来预留命名空间（本次不实现，仅占位防撞名）

| 命名空间 | 中文 | 预留子命令 | 对应站点功能 |
| --- | --- | --- | --- |
| `forum` | `论坛` | `post` `reply` `list` `search` | 话题论坛 |
| `fan` | `同人` | `add` `list` `draft` | 同人创作 |
| `review` | `书评` | `add` `list` | 书评打分 |
| `dl` | `下载` | `chapter` `pack` | 选章/选集下载 |
| `admin` | `管理` | `user` `work` `whitelist` | 管理后台 |

## 三、选项规范

### 3.1 短选项全局分配表（固定，跨命令语义一致）

| 短 | 长 | 值 | 含义 | 用于 |
| --- | --- | --- | --- | --- |
| `-h` | `--help` | 无 | 显示帮助 | 全部命令 |
| `-k` | `--keyword` | 字符串 | 搜索关键词 | work search |
| `-t` | `--title` | 字符串 | 作品标题 | work add |
| `-a` | `--author` | 字符串 | 作者名 | work add |
| `-s` | `--summary` | 字符串 | 一句话简介 | work add |
| `-l` | `--link` | `名=URL` | 外链，**可重复** | work add |
| `-c` | `--code` | 字符串 | 验证码 | auth bind |
| `-g` | `--group` | 群号 | 目标群，**可重复** | sync member/avatar |
| `-n` | `--limit` | 整数 | 返回/处理数量上限 | work hot/search、sync avatar |

### 3.2 刻意不给短选项的长选项

| 长 | 理由 |
| --- | --- |
| `--type` | 值本身较长（`novel`/`小说`），缩写省不了几个字；且 `-t` 已固定给 `--title` |
| `--tags` | 低频，且值含逗号易与短选项连写混淆 |
| `--source` | 低频（仅同人文绑原作） |
| `--all` | **安全**：`-a` 已固定给 `--author`；且「同步全部群」误触代价高 |
| `--force` | **安全**：破坏性开关，强制打全名，避免手滑 |

### 3.3 值语法

| 形式 | 支持 | 说明 |
| --- | --- | --- |
| `--limit 10` | ✅ | 空格分隔（主形式） |
| `--limit=10` | ✅ | 等号形式，GNU 标准 |
| `-n 10` | ✅ | 短选项 + 空格 |
| `-n10` | ✅ | 短选项连写，GNU 标准 |
| `-a "爱潜水的 乌贼"` | ✅ | 引号包裹含空格值，`shlex.split` 处理 |
| `-g 123 -g 456` | ✅ | 可重复选项收集为 list |
| `--tags 百合,已完结` | ✅ | 逗号分隔，宽容解析 |
| `--tags 百合 --tags 已完结` | ✅ | 重复形式，等价于上一行 |
| `--all` `--force` `-h` | ✅ | 布尔开关，不消费后续 token |

**不支持**短选项聚合（`-an 10` 这种），因为 `-a` 带值，聚合语义会产生歧义；遇到 `-an` 一律按「`-a` 的值为 `n`」解析，符合 GNU 惯例。

### 3.4 `--type` 值的中英映射（宽容解析）

| 规范值 | 接受的中文 | 站点 label |
| --- | --- | --- |
| `novel` | 小说 | 小说 |
| `anime` | 番剧、动漫 | 番剧/动漫 |
| `movie` | 电影、影片 | 电影 |
| `gallery` | 图集、图、写真 | 图集 |
| `fanwork` | 同人、同人文 | 同人文 |
| `other` | 其他（默认） | 其他 |

> 类型清单以 `backend/app/models.py` 的 `WorkType` 为唯一真源，中文 label 对齐
> `frontend/src/views/WorksView.vue` 的筛选下拉。
> ⚠️ `backend/app/schemas.py:186` 的注释写的是 `novel/anime/comic/game/fanwork/other`，
> 与 `models.WorkType` **不一致**（`comic`/`game` 并不存在），本次一并修正该注释。

## 四、完整命令清单

### 4.1 `/work hot` — 热门作品榜

```
用法：/work hot [选项]
别名：/作品 热门 · /热门 · /hot

  -n, --limit <数>   返回条数，默认 5，上限 20
  -h, --help         显示帮助

示例：
  /热门
  /hot -n 10
  /作品 热门 --limit 3
```

### 4.2 `/work search` — 关键词搜作品

```
用法：/work search --keyword <词> [选项]
别名：/作品 搜索 · /搜索 · /search

  -k, --keyword <词>   搜索关键词（必填）
      --type <类型>    按类型过滤：novel|anime|movie|gallery|fanwork|other（或中文）
  -n, --limit <数>     返回条数，默认 10，上限 50
  -h, --help           显示帮助

示例：
  /搜索 -k 诡秘之主
  /search --keyword 百合 --type novel -n 20
  /作品 搜索 -k 诡秘
```

> 缺 `--keyword` 时报错并打印 usage，不做模糊兜底。
> `--type` 过滤需后端 `/bot/works/search` 增加 `type` 查询参数（见 §七改动清单）。
> ⚠️ 该接口现有 `limit: int = Query(10, ge=1, le=20)`，上限 20 与本规范的 50 不符，
> 需同批把 `le=20` 放宽到 `le=50`；否则群友传 `-n 50` 会被后端 422 拒绝，
> 且报错是 FastAPI 的英文 JSON，群聊里完全不可读。

### 4.3 `/work add` — 提交作品入库（安利）

```
用法：/work add --title <作品名> [选项]
别名：/作品 安利 · /安利 · /recommend

  -t, --title <名>       作品标题（必填）
  -a, --author <名>      作者
      --type <类型>      novel|anime|movie|gallery|fanwork|other（或中文），默认 other
  -s, --summary <简介>   一句话简介
      --tags <标签>      标签，逗号分隔或重复给出
  -l, --link <名=URL>    外链，可重复，如 -l 起点=https://...
      --source <作品ID>  绑定原作 ID（同人文用）
  -h, --help             显示帮助

示例：
  /安利 -t 诡秘之主
  /recommend -t 诡秘之主 -a 爱潜水的乌贼 --type novel
  /作品 安利 -t 某同人 --source 12 --tags 百合,连载中 -s 短篇甜文
  /安利 -t 某番 --type 番剧 -l B站=https://www.bilibili.com/xxx
```

> 打通后端 `BotWorkSubmitIn` 已支持但插件从未传过的 6 个字段，**本次功能增量最大的一项**。
> 提交者自动挂 `recommender`、同名作品返回 duplicate 提示等现有行为不变。

### 4.4 `/auth bind` — 注册绑定码核验

```
用法：/auth bind --code <验证码> [选项]
别名：/账号 绑定 · /绑定 · /bind

  -c, --code <码>   4~8 位验证码（必填）
  -h, --help        显示帮助

示例：
  /绑定 -c 123456
  /bind --code 123456
```

**裸数字兜底通道（保留）**：群友 @机器人 直接发一串 4~8 位数字（不带任何命令），仍按绑定核销处理。

- 这是**独立的消息规则**，不是 `/auth bind` 的位置参数，与 B 项「严格全选项」不冲突。
- 保留理由：注册流程是站点唯一的准入通道，页面给出码后群友最自然的动作就是直接把码发给机器人。若强制打 `/绑定 -c 123456`，手抄场景下极易出错，会直接卡住新人注册。
- 兜底仅在**消息去空白后整体就是一个 4~8 位数字**时触发，避免把群友聊天里的普通数字误判为验证码。

群消息 best-effort 撤回验证码（OneBot 通道）、openid ↔ QQ 映射等现有逻辑全部不变。

### 4.5 `/sync member` — 重同步群成员白名单（SUPERUSER）

```
用法：/sync member [选项]
别名：/同步 成员

  -g, --group <群号>   目标群，可重复；缺省为 .env 的 SYNC_GROUPS
      --all            同步 SYNC_GROUPS 配置的全部群
      --force          拉到 0 个成员时仍执行「标记其余人退群」（危险，默认关闭）
  -h, --help           显示帮助

示例：
  /同步 成员 --all
  /sync member -g 123456 -g 789012
  /sync member --all --force
```

> 命令名由 `sync_member`（下划线）改为 `sync member`（两级 + kebab-case）。
> `--force` 对应现有 `_sync_one_group(mark_inactive_others=...)` 的防误清保护，改为显式可控开关。
> 缺 `-g` 与 `--all` 时沿用现有行为（取 SYNC_GROUPS），不报错。

### 4.6 `/sync avatar` — 同步群成员头像（SUPERUSER）

```
用法：/sync avatar [选项]
别名：/同步 头像

  -g, --group <群号>   目标群，可重复；缺省为 SYNC_GROUPS
      --all            同步 SYNC_GROUPS 全部群
  -n, --limit <数>     本次最多同步多少个，默认取 AVATAR_SYNC_BATCH_LIMIT（100）
  -h, --help           显示帮助

示例：
  /同步 头像 --all
  /sync avatar -g 123456 -n 50
```

> `-n/--limit`、`-g/--group` 打通已有 `sync_avatars(bot, group_ids, limit)` 签名，此前参数存在却未暴露。
> 优先级：命令行 `-n` > `.env` 的 `AVATAR_SYNC_BATCH_LIMIT` > 内置 100。

### 4.7 `/help` — 命令发现（**新增**）

```
用法：/help [命令名]
别名：/帮助

  无参数    → 分组列出全部命令（群友可用 / 管理员）+ 一行说明
  带命令名  → 显示该命令完整 usage、选项表、示例

示例：
  /帮助
  /help 安利
  /help work add
  /help recommend      （快捷别名与全路径等价）
```

**输出格式约定**（QQ 消息有长度限制，需精简）：

```
📖 群资源站机器人命令

【作品】
/热门 -n 10          热门作品榜
/搜索 -k <词>        搜索作品
/安利 -t <名>        提交作品入库

【账号】
/绑定 -c <码>        注册绑定码核验

【管理】（仅管理员）
/同步 成员 --all     重同步群成员白名单
/同步 头像 --all     同步群成员头像

```

要求：全量输出控制在 **800 字符内**；`/帮助 <命令>` 的输出与该命令 `-h` 完全一致，共用同一份元数据。

## 五、报错与帮助规范

所有报错**中文**，且必须带可执行的下一步，禁止只回「参数错误」。

| 场景 | 回复模板 |
| --- | --- |
| 缺必填选项 | `⚠️ 缺少必填参数 --keyword\n\n用法：/搜索 --keyword <词>\n输入 /帮助 搜索 查看全部参数` |
| 未知长选项 | `⚠️ 未知参数：--keywrod\n你是不是想用 --keyword？\n\n输入 /帮助 搜索 查看全部参数` |
| 未知短选项 | `⚠️ 未知参数：-x\n\n输入 /帮助 搜索 查看全部参数` |
| 选项缺值 | `⚠️ 参数 --limit 后面需要一个值\n例：--limit 10` |
| 值类型非法 | `⚠️ --limit 需要数字，收到「abc」` |
| 值超出范围 | `⚠️ --limit 最大 20，收到 100` |
| `--type` 值非法 | `⚠️ --type 只支持 novel/anime/movie/gallery/fanwork/other（或对应中文），收到「xxx」` |
| 未知子命令 | `⚠️ 没有「/作品 xxx」这个命令\n\n该命名空间可用：hot(热门) · search(搜索) · add(安利)` |
| 无权限 | `⚠️ /同步 成员 仅管理员可用` |

**未知选项的近似纠正**：用编辑距离 ≤2 匹配已注册选项名，命中就提示「你是不是想用 X」。这是 GNU 工具（如 git）的标准体验，群聊场景下对手滑打错字帮助很大。

`-h` 出现在任何位置都优先生效（`/搜索 -k 诡秘 -h` 也返回帮助，不执行搜索）。

## 六、实现方案

### 6.1 为什么不用 nonebot 原生 `on_command` / `argparse`

| 方案 | 否决理由 |
| --- | --- |
| `on_command(("work","search"))` 元组命令 | 依赖 `COMMAND_SEP`，无法表达中英混搭（4 种组合）+ 一级快捷别名同时指向同一 handler；且参数解析仍要自己做 |
| `on_shell_command` + `argparse` | argparse 报错为英文、面向终端、默认 `sys.exit()`（在 nonebot handler 里需层层包 try）；subparser 的 usage 文案不受控，无法输出中文友好提示与近似纠正 |
| 第三方 `nonebot-plugin-alconna` 等 | 引入重依赖，学习成本高于自写；本项目命令规模（7 个）不需要 |

**采用：自写 dispatcher + 命令元数据表驱动**。解析核心约 150 行，无新增依赖。

### 6.3 dispatcher 实现要点

```python
# cli_router.py 核心结构（示意）
_cli = on_message(rule=_CommandRule(), priority=10, block=True)

@_cli.handle()
async def _dispatch(bot: Bot, event: Event):
    ...
```

`_CommandRule` 必须在 **rule 阶段**就判定「这是不是已注册命令」，因为 nonebot 的 `block` 是静态的、handler 内无法动态取消：

1. 取 `event.get_plaintext()`，归一化全角空格/横线，strip 掉 mention 段残留
2. 要求以 `/` 开头（配合 `COMMAND_START=["/"]`）
3. 切出前两段，查命令注册表（含中英别名与快捷别名）
4. 命中 → 进入 handler，`block=True` 阻止后续插件
5. 未命中 → rule 返回 False，**完全放行**，不影响群友正常聊天和其他插件

### 6.4 QQ 消息的特殊处理（现有代码全部缺失）

| 情况 | 处理 |
| --- | --- |
| 全角空格 `　` | 归一化为半角空格 |
| 全角横线 `－－` `——` `—` | 归一化为 `--` |
| 中文全角引号 `“”` `‘’` | 归一化为 `"` `'`（供 `shlex` 解析） |
| `@机器人` mention 段 | `get_plaintext()` 后 strip 首部空白与 mention 文本 |
| QQ 客户端自动插入的不可见字符 | 过滤零宽字符（`\u200b` 等） |
| 引号包裹含空格值 | `shlex.split(posix=True)` 原生支持 |
| 可重复选项 | 收集为 list，顺序保留 |
| 布尔开关 | 不消费后续 token |
| 未知选项 | 报错 + usage + 近似纠正，**不静默忽略** |
