## R1 · 🔴 站点没有 https（D3 前置阻塞）

实测：`http://59.110.163.88:4173/` → 200（0.08s）；`https://…:4173/` → 000；`https://59.110.163.88:5244/` → 000。
影响：QQ markdown 图片要求公网可访问 URL；仅有 http + IP 的组合能否被平台接受、以及客户端是否强制 https，存在口径不一致的资料（有第三方称 NTQQ 强制 HTTPS 并校验 Referer/CORS）。
处置：M0 用沙箱群实测一张真实渲染图，以能否显示为唯一判定标准，不靠文档推断。

## R2 · 🔴 平台能力与报备门槛

## R3 · 🟠 渲染图直链鉴权形同虚设（安全，独立于本任务也应修）

实测：同一 URL 带 sign / 去 sign / 填错 sign，**三者都返回 200 与同一张 187023B 的 PNG**。

处置：建议单列一个安全项，与 M4 解耦，不要顺手改。可选方向：alist 开启签名强制校验，或改走 4173 同源代理输出。
