## 3. 官方文档依据（两个独立来源对上）

### ① 官方 markdown 消息文档

`bot.q.qq.com/wiki/develop/api-v2/server-inter/message/type/markdown.html`

「图片」小节里**唯一**那张示例：

```
![text #208px #320px](https://resource5-1255303497.cos.ap-guangzhou.myqcloud.com/.../building.png)
```

即**官方语法是 `![alt #宽px #高px](url)`**，不是标准 markdown 的 `![alt](url)`。
同页还写了：「对于 markdown 消息内的图片资源，请使用可在公网访问的资源 url，**开放平台会下载转存该资源**。」

### ② 腾讯自家 openclaw-qqbot 插件

`tencent-connect/openclaw-qqbot`（腾讯官方仓库）专门实现了「**Size hint injection**」：

- 把标准 `![alt](url)` 转成 `![#Wpx #Hpx](url)`
- 做法：**HTTP Range 拉前 64KB**，解析 PNG IHDR / JPEG / GIF / WebP 头取真实宽高
- 文档原文：*"QQ Bot's Markdown format **requires** a special image syntax that includes width and height hints. This improves rendering performance by allowing the client to **reserve space before the image loads**."*

**官方文档从头到尾没提过手机端/电脑端差异** —— 这是官方自己的实现细节，不是有意支持的端差异。

## 4. 出图的三条件模型

出图需要**同时**满足：

| # | 条件 | 责任方 | 不满足的表现 |
|---|---|---|---|
| ① | 图片资源能被平台转存 / 客户端能加载 | 平台 + 网络 | 无图 / 卡在"加载中" |
| ② | markdown 图片语法**带尺寸提示** | **客户端侧** | 图片节点建不起来 → 降级成 alt 文本 `[alt]` |
| ③ | 客户端支持渲染 | 客户端侧 | 永远 `[alt]` |

- 电脑端出图（A/D）：①✅ ②❌ ③✅（桌面端有 fallback 能自行取尺寸）→ 仍能显示
- 手机端全 `[alt]`：**② 是主因**（加了尺寸就出图，已确证）
- G 卡"加载中"：②✅（尺寸解析正确）但 ① 待解（自建未备案域名）

## 5. D3 可执行的硬约束（三条）

1. **图片语法必须带尺寸提示** `![alt #Wpx #Hpx](url)`，且发前**自动探测宽高**
   （Range 拉前 64KB 解析图片头，照 openclaw-qqbot 的 `image-size.ts` 做）。
2. **图片地址要能被加载**：裸 IP、外部公网 https 实测可用；**自建未备案域名卡在"加载中"**（未确认是转存中还是不通）→ 长期建议已备案域名 / CDN。
3. **一次触发最多被动回 5 条**（`40034128`）；`msg_type` 单值，markdown 与图片不能同条。
